SYSTEM ARCHITECTURE

AlgoTrace: Pure Functional Engine Architecture

Problem Statement & Architectural Decision

Traditional algorithm visualizers mutate state directly in UI animation loops (e.g. setInterval or requestAnimationFrame). This causes state drift, breaks backward stepping, and creates memory leaks when switching algorithms. AlgoTrace solves this with a strictly decoupled pure execution engine.

Execution Flow Pipeline

User Input / Array Presets ↓ Validation Layer (Verifies sorted preconditions for Binary/Jump Search, rejects negative edges for Dijkstra) ↓ Pure Execution Engine (Algorithms execute to completion returning an immutable Step[] array) ↓ Execution Manager (Deterministic navigation: current step pointer, playback loop, scrub slider) ↓ Reactive Presentation Layer (ArrayVisualizer, SearchVisualizer, GraphVisualizer, PseudocodeViewer)

Algorithms Implemented (17 Total)

Sorting (8):
  • Bubble Sort, Selection Sort
  • Insertion Sort, Merge Sort
  • Quick Sort (Lomuto Partitioning)
  • Heap Sort (Max-Heap Sift-Down)
  • Shell Sort, Cocktail Shaker Sort
Searching & Graphs (9):
  • Linear Search, Binary Search, Jump Search
  • Breadth-First Search (animated FIFO queue)
  • Depth-First Search (animated LIFO stack)
  • Dijkstra's Algorithm (tentative distance table)
  • Bellman-Ford (negative cycle detection)
  • Prim's Algorithm (MST weight accumulator)

SYSTEM ARCHITECTURE

CookPilot: Weighted Decision Engine & State Machine

Mathematical Ingredient Scoring Model

Unlike fuzzy search or generative LLMs that hallucinate non-existent combinations, CookPilot uses a deterministic weighted formula:

Score = (Matched_Required / Total_Required) * 0.85 + (Substituted_Items * Substitution_Weight) + (Matched_Garnishes / Total_Garnishes) * 0.15

Valid culinary substitutions are credited at 40% to 80% weight depending on culinary role (e.g. Greek yogurt replacing sour cream).

Finite State Machine Lifecycle

IDLE ──(Start Cooking)──> PREPARING ──(Heat Pan)──> HEATING │ COMPLETED <──(Finish All Steps)── COOKING <─────────────┘ ├──(Timer Delay)──> WAITING └──(Flame Change)──> ADJUST_HEAT

The state machine prevents improper transitions, such as completing a step with an active countdown timer without explicit confirmation.

Web Audio API Offline Chimes

Generates custom audio frequencies directly via the browser's AudioContext oscillator and gain nodes, eliminating external MP3 audio asset requests and working 100% offline.

CortX: Distributed Browser Triage & Queue System

Priority Queue & Emergency Sorting

Emergency arrivals are scored on arrival using medical severity metrics (heart rate, trauma score, respiratory distress). CortX implements a client-side priority queue that re-indexes patients immediately when critical conditions are logged.

Rolling-Window Consultation ETA

ETA_Department = (Σ Duration of last 25 resolved consultations in Department / 25) * Active_Patients_Ahead_In_Queue

Dynamically adapts to real-world physician pace rather than static arbitrary estimates.

Multi-Tab Real-Time Inter-Process Communication

By combining the BroadcastChannel API with fallback StorageEvent listeners, when a triage nurse registers a patient or a doctor finishes a consultation in one tab, all other active browser windows (reception, doctor room, waiting hall) update within 2 milliseconds without server requests.
